# שלב 5 — Content: תבניות עם אזורים, Widgets ו-Widget SDK ✅

**מטרה:** מסך שמציג כמה תכנים במקביל, למשל וידאו באזור הראשי, שעון עם תאריך עברי בצד וטקסט רץ למטה. בנוסף: Widgets מובנים, וממשק מתועד שבעזרתו הקהילה יכולה לפתח Widgets חדשים.

## 3. אבטחה

- **Fetch מוגן (SSRF):**
  - פרוטוקולים http/https ופורטים 80/443 בלבד.
  - כתובת ה-IP נבדקת **ברגע החיבור** (`lookup` מותאם), כך ש-DNS rebinding לא עוקף את הבדיקה.
  - חסומים: loopback, רשתות פרטיות (RFC1918), link-local (כולל 169.254.169.254 של שירותי מטא-דאטה בענן), CGNAT, multicast, IPv6 ULA ו-link-local, וכתובות IPv4-mapped.
  - עד 3 הפניות (redirects), כל אחת נבדקת מחדש. ‏timeout של 5 שניות, גוף תשובה עד 1MB.
  - **בבדיקות בלבד:** ‏`WIDGET_FETCH_ALLOW_PRIVATE=true`. אסור בפרודקשן (נבדק בטעינת ה-ENV).
- **‏RSS:**
  - מפוענח עם fast-xml-parser, בלי DTD וישויות חיצוניות.
  - נשמר טקסט בלבד: HTML מוסר, והנגן מציג `textContent`.
- **הגדרות Widget:** נבדקות בשרת מול סכמה. URL-ים חייבים להיות https.
- **CSP של הנגן:** נוסף `frame-src https:` ל-Widget דף האינטרנט. ה-iframe נטען עם `sandbox="allow-scripts allow-same-origin"` ו-`referrerpolicy="no-referrer"`.

## 4. מודל נתונים (Migration `0004_layouts_widgets`)

- **`layouts`:** ‏`id`, `org_id`, `name`, `width`, `height`, `background`.
- **`layout_zones`:** ‏`layout_id`, `position`, `name`, `x`, `y`, `w`, `h`, `z`, `playlist_id`. כשפלייליסט נמחק, האזור נשאר ריק (`ON DELETE SET NULL`).
- **`widgets`:** ‏`id`, `org_id`, `type`, `name`, `config` (jsonb).
- **`playlist_items`:** ‏`media_id` הופך ל-nullable, נוסף `widget_id`, ו-CHECK שדורש בדיוק אחד מהשניים.
- **`screens`:** נוסף `layout_id` (‏nullable). כשהוא מוגדר הוא מחליף את `playlist_id`.

## 5. API (‏CMS)

| Endpoint                                                                                    | הרשאה                         |
| ------------------------------------------------------------------------------------------- | ----------------------------- |
| `GET/POST layouts` · `GET/PATCH/DELETE layouts/:id` (כולל עדכון האזורים בפעולה אחת)         | קריאה: VIEWER · כתיבה: EDITOR |
| `GET/POST widgets` · `GET/PATCH/DELETE widgets/:id` · `GET widgets/:id/data` (תצוגה מקדימה) | קריאה: VIEWER · כתיבה: EDITOR |
| `GET widget-types` (סוגים זמינים, כולל אם מזג אוויר מוגדר)                                  | VIEWER                        |

**נגן:** ‏`GET /player/v1/widgets/:id/data` (Bearer). רק Widgets של הארגון של המסך.

## 6. נגן

- **אזורים:** ‏Layout ממוקם בתוך המסך עם שמירת יחס (letterbox). כל אזור מנגן את הפלייליסט שלו באופן עצמאי.
- **גודל ביחס לאזור:** הנגן מגדיר לכל אזור משתני CSS ‏`--zone-w` ו-`--zone-h` (בפיקסלים), וה-Widgets מחשבים מהם את גודל הטקסט. זה עובד גם בדפדפני טלוויזיה ישנים. בדפדפנים חדשים האזור הוא גם `container-type: size`.
- **אזור עם פריט יחיד** (למשל טקסט רץ) לא נטען מחדש בכל סבב.
- **‏Widgets רשומים ב-registry** לפי הממשק של `widget-sdk`. ‏Widget עם נתונים (RSS, מזג אוויר) מקבל `ctx.fetchData()`, ונתוני Cache נשמרים בנגן לעבודה Offline.

## 7. CMS

- **עמוד Layouts:** רשימה, ויצירה מתבנית.
- **עורך Layout:**
  - טבלת אזורים עם שדות X/Y/רוחב/גובה/שכבה ופלייליסט.
  - תצוגה מקדימה גרפית (בשביל ההבנה החזותית בלבד; כל העריכה נעשית בטופס).
  - כפתורי "הוספת אזור" ו"הסרה".
  - ולידציה של גבולות הקנבס.
- **עמוד Widgets:** רשימה, יצירה לפי סוג, וטופס ייעודי לכל סוג.
- **עורך הפלייליסט:** לשונית "Widgets" בנוסף לספריית המדיה.
- **מסכים:** בחירה בין "פלייליסט" ל-"Layout".

## 8. בדיקות

- **יחידה:**
  - סכמות Widgets.
  - SSRF guard: כתובות פרטיות IPv4/IPv6/mapped, redirect לכתובת פרטית, סכמה ופורט לא חוקיים.
  - פענוח RSS: HTML מוסר, ישויות ומגבלות.
  - נרמול נתוני מזג אוויר.
  - מספור עברי (גימטריה).
- **Integration:**
  - CRUD ו-IDOR של Layouts ו-Widgets.
  - ‏Manifest עם אזורים ו-Widgets, תקף לפי הסכמה.
  - נקודת הנתונים מול שרת RSS מקומי.
  - Webpage באותו origin נדחה.
- **נגן:** הרצת אזורים, Widgets (שעון עם תאריך עברי, כיוון טקסט רץ, QR, סבב RSS, iframe שנחסם).
- **‏E2E:** ‏Layout "ראשי + טקסט רץ" עם שעון וטקסט רץ, משויך למסך → הנגן מציג את שניהם. ‏axe על העמודים החדשים.

### החלטות שהתקבלו במהלך הפיתוח

- **שגיאות ולידציה עם סיבה:** refine מותאם יכול להחזיר סיבה ספציפית (`out_of_bounds`, `own_origin`, `unavailable`), וה-CMS מתרגם אותה.
- **מגבלת שליפות:** עד 120 שליפות חיצוניות בשעה לכל ארגון (רק כשאין Cache), והמתנה של דקה אחרי כישלון. כך המערכת לא הופכת לכלי להצפת אתרים.
- **מכסות:** עד 1000 Widgets ו-500 Layouts לארגון.
- **אזורים לא נבנים מחדש:** עדכון תוכן שלא משנה את גאומטריית האזור לא מהבהב, ו-Widget זהה נשאר על המסך.
- **מזג אוויר מ-endpoint של המפעיל:** הכתובת נקבעת ע"י המפעיל (יכולה להיות מופע פנימי), ולכן היא מותרת גם ברשת פרטית. כתובות פידי RSS, שמגיעות מהמשתמשים, חסומות לרשתות פרטיות.

### באג שנמצא ותוקן

- **בדיקות Integration לא רצו דרך `pnpm test`:** ‏Turborepo פועל במצב env קפדני ומסנן משתני סביבה שלא הוצהרו, כך ש-`RUBINNY_INTEGRATION` לא הגיע לבדיקות והן דולגו בשקט (גם ב-CI). נוסף `passThroughEnv` למשימת `test` ב-`turbo.json`, ועכשיו כל 209 בדיקות השרת רצות גם דרך Turborepo.

### הגדרות חדשות

- ‏`WEATHER_API_URL`, ‏`WEATHER_API_KEY` — מזג אוויר (כבוי כברירת מחדל). פירוט ב-`deploy/.env.example`.
- ‏`WIDGET_FETCH_ALLOW_PRIVATE` — לבדיקות בלבד. השרת מסרב לעלות איתו בפרודקשן.

### מגבלות ונושאים לבדיקה

- **פרמטרים של Open-Meteo:** ‏`current`, ‏`daily`, ‏`forecast_days`, ‏`temperature_unit` ו-`apikey` — **דורש אימות מול התיעוד הרשמי** לפני הפעלה בפרודקשן.
- **רישוי מזג אוויר:** ה-API החינמי של Open-Meteo מיועד לשימוש לא-מסחרי. השימוש המסחרי מחייב מנוי או מופע עצמי — **דורש בדיקה משפטית** של המפעיל.
- **דפי אינטרנט:** אתרים רבים חוסמים הצגה בתוך iframe (‏`X-Frame-Options`/`frame-ancestors`). האתר המוצג מקבל את כתובת ה-IP של המסך. מצוין במדיניות הפרטיות.
- **אמוג'י במזג אוויר:** מסכים בלי גופן אמוג'י יציגו תיאור טקסטואלי בלבד.
- **עורך Layout:** העריכה היא בטופס (נגיש במקלדת ובקורא מסך). גרירה בעכבר תתווסף בהמשך.
