# שלב 18: הזמנת חדרים, מדריך בניין, יומן אירועים וזמני תפילה (תוכנית, ממתינה לאישור)

## 1. סיכום ההבנה

ארבעה פיצ'רים חדשים, לפי הבחירות שלך:

1. **הזמנת חדרים:**
   - **ניהול:** חדרים והזמנות מנוהלים בלוח הניהול.
   - **מסך ליד החדר:** מציג פנוי או תפוס, את הפגישה הנוכחית ואת הבאה.
   - **הזמנה מהמסך:** במסך מגע יש כפתור "הזמנה עכשיו" שדורש קוד PIN ארגוני.
   - **בלי חשבונות חיצוניים:** אין סנכרון עם Google או Microsoft.
2. **מדריך בניין:** מסך לובי עם חברות ומחלקות לפי קומה וחדר, עם סינון במגע וחץ כיוון.
3. **יומן אירועים:** הצגת אירועים קרובים מקישור iCal ‏(ICS), כרשימה או כתצוגה שבועית.
4. **זמני תפילה וזמני היום:**
   - **מה מוצג:** זמני היום, כניסת שבת ויציאתה וזמני תפילה קבועים, לפי מיקום, עם התאריך העברי שכבר קיים במערכת.
   - **אישור הלכתי:** החישובים דורשים בדיקה של רב לפני שימוש ציבורי.

## 3. User Stories

**הזמנת חדרים**

1. **מנהלת משרד:** מגדירה חדרים ("חדר ישיבות גדול", קומה 3, 12 מקומות) ו-PIN לארגון.
2. **עובד:** בלוח הניהול רואה את היום של כל החדרים, בוחר שעה פנויה, ומזמין עם כותרת. אם יש התנגשות, הוא מקבל הודעה ברורה.
3. **עובדת ליד החדר:** רואה על הטאבלט "פנוי עד 14:00". היא נוגעת ב"הזמנה 30 דק'", מקלידה PIN, והמסך הופך לאדום "תפוס עד 13:30".
4. **מבקר:** רואה "תפוס · הפגישה הבאה 15:00" ולא מקבל שום פרט אישי.
5. **משתמש מקלדת או קורא מסך בלוח הניהול:** יכול להזמין דרך טופס נגיש, ולא רק בגרירה על לוח הזמנים.

**מדריך בניין**

6. **מנהל הבניין:** מוסיף רשומות (שם, קומה, חדר, קטגוריה, כיוון) ומעלה מפה לכל קומה.
7. **מבקר בלובי:** נוגע ב"קומה 2" או ב"רפואה", רואה את הרשימה המסוננת עם חץ ומפה. אחרי דקה בלי נגיעה המסך חוזר לבד.

**יומן אירועים**

8. **רכזת מתנ"ס:** מדביקה קישור iCal של היומן הציבורי. המסך מציג את 6 האירועים הבאים, או את השבוע.

**זמני תפילה**

9. **גבאי:** מגדיר מיקום (עיר מרשימה, או קואורדינטות), שיטת חישוב ודקות הדלקת נרות (18, 30 או 40 בירושלים). הוא מוסיף תפילות קבועות ("שחרית 06:30", "מנחה: 15 דק' לפני השקיעה").
10. **מתפלל:** רואה על המסך את התאריך העברי, את זמני היום ואת כניסת השבת הקרובה.

## 4. מסכים

**לוח הניהול**

- **"חדרים" (תפריט חדש):**
  - רשימת חדרים, עם יצירה ועריכה.
  - לוח יום: שורה לכל חדר וציר שעות, עם מעבר בין ימים.
  - טופס הזמנה (חדר, תאריך, משעה, עד שעה, כותרת).
  - כפתור "ההזמנות שלי".
- **"הגדרות ארגון":** שדה "PIN להזמנה ממסך", שנשמר מוצפן (hash). אפשר להחליף או לבטל אותו.
- **עורכי Widgets חדשים:**
  - **חדר:** בחירת חדר.
  - **מדריך בניין:** טבלת רשומות, כמו עורך התפריט.
  - **יומן:** קישור ICS ותצוגה.
  - **זמנים:** מיקום, שיטה ותפילות.

**הנגן**

- **‏Widget חדר:**
  - **ירוק "פנוי", אדום "תפוס":** הצבע אינו הסימן היחיד, יש גם טקסט ואייקון.
  - **מה מוצג:** שם החדר, הפגישה הנוכחית, הבאות, ושעון.
  - **בטאבלט מגע:** כפתורי הזמנה ומקלדת PIN על המסך.
- **מדריך:** לשוניות קומה וקטגוריה, רשימה, חץ ומפת קומה.
- **יומן:** רשימה או שבוע.
- **זמנים:** לוח זמנים מעוצב, עם הדגשת הזמן הבא.

## 5. ארכיטקטורה

- **Widgets חדשים** (בתוך `WIDGET_CONFIG_SCHEMAS`):
  - `room`: ‏`{ roomId, locale, allowBooking, theme }`.
  - `directory`: ‏`{ entries[], floors[], categories[], idleSeconds, locale }`.
  - `calendar`: ‏`{ url, view: 'agenda'|'week', maxEvents, locale }`.
  - `zmanim`: ‏`{ place: {lat, lon, tz, elevation?}, method, candleMinutes, israel, prayers[], locale }`.
- **‏`calendar` הוא Widget נתונים** (`DATA_WIDGET_TYPES`). השרת מושך ומפענח את ה-ICS, כמו ב-RSS. רק נתונים מוכנים נשלחים לנגן: כותרת, התחלה, סוף, מיקום ו"כל היום".
- **‏`room` הוא Widget נתונים** שמקורו במסד הנתונים שלנו. הסטטוס מתעדכן מיידית דרך ה-WebSocket הקיים (`screen-events`) כשהזמנה משתנה, ובנוסף נשלפת כל 60 שניות כגיבוי.
- **‏`directory` ו-`zmanim`:** מחושבים בנגן בלבד. אין בהם קריאות רשת.
- **כתיבה מהנגן (חדש):** עד היום הנגן רק קרא מהשרת, חוץ מ-heartbeat ו-proof of play. שתי נקודות כתיבה חדשות, רק לחדרים, עם בדיקות קשיחות (סעיף 8).

## 6. סכמת מסד הנתונים (migration ‏`0021_rooms`)

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;  -- for the no-overlap constraint

CREATE TABLE rooms (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  name text NOT NULL CHECK (char_length(name) BETWEEN 1 AND 80),
  location text CHECK (char_length(location) <= 120),       -- "Floor 3, east wing"
  capacity int CHECK (capacity BETWEEN 1 AND 1000),
  show_titles boolean NOT NULL DEFAULT false,                -- titles on the room screen
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (org_id, name)
);

CREATE TABLE room_bookings (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  room_id uuid NOT NULL REFERENCES rooms(id) ON DELETE CASCADE,
  during tstzrange NOT NULL CHECK (NOT isempty(during) AND upper(during) - lower(during) <= interval '12 hours'),
  title text CHECK (char_length(title) <= 120),
  booked_by uuid REFERENCES users(id) ON DELETE SET NULL,   -- null = booked at the screen
  screen_id uuid REFERENCES screens(id) ON DELETE SET NULL, -- set when booked at a screen
  created_at timestamptz NOT NULL DEFAULT now(),
  EXCLUDE USING gist (room_id WITH =, during WITH &&)       -- no double booking, even under races
);
CREATE INDEX room_bookings_room_time ON room_bookings USING gist (room_id, during);

ALTER TABLE organizations ADD COLUMN room_pin_hash text;     -- scrypt, like passwords
```

- **RLS:** לפי `org_id`, באותה תבנית כמו בשאר הטבלאות (שלב 10c).
- **‏`btree_gist`:** כלול באימג' הרשמי של PostgreSQL ‏(contrib). התקנה על מסד קיים דורשת הרשאת יצירת extension. בדיקה של זה תהיה חלק מה-migration ומ-`UPGRADING.md`.
- **שמירה:** הזמנות שהסתיימו נמחקות אחרי 90 יום, בתחזוקה היומית הקיימת. אפשר להגדיר זמן אחר.

## 7. API

**לוח הניהול** (מחייב התחברות; תמיד בתוך `orgs/:orgId`, עם בדיקת חברות ותפקיד):

| Method | Path                                        | תפקיד                                     |
| ------ | ------------------------------------------- | ----------------------------------------- |
| GET    | `/api/v1/orgs/:orgId/rooms`                 | VIEWER                                    |
| POST   | `/api/v1/orgs/:orgId/rooms`                 | ADMIN                                     |
| PATCH  | `/api/v1/orgs/:orgId/rooms/:roomId`         | ADMIN                                     |
| DELETE | `/api/v1/orgs/:orgId/rooms/:roomId`         | ADMIN (מבטל גם את כל ההזמנות שלו)         |
| GET    | `/api/v1/orgs/:orgId/room-bookings?from&to` | VIEWER (עד 31 ימים בבקשה)                 |
| POST   | `/api/v1/orgs/:orgId/room-bookings`         | VIEWER                                    |
| PATCH  | `/api/v1/orgs/:orgId/room-bookings/:id`     | המזמין עצמו, או ADMIN                     |
| DELETE | `/api/v1/orgs/:orgId/room-bookings/:id`     | המזמין עצמו, או ADMIN                     |
| PUT    | `/api/v1/orgs/:orgId/settings/room-pin`     | ADMIN, עם אימות דו-שלבי כמו בפעולות אדמין |

**הנגן** (טוקן המסך):

| Method | Path                                        | מה                                    |
| ------ | ------------------------------------------- | ------------------------------------- |
| GET    | `/player/v1/widgets/:widgetId/data`         | קיים. מחזיר גם סטטוס חדר ואירועי יומן |
| POST   | `/player/v1/rooms/:roomId/bookings`         | `{ minutes: 15\|30\|60, pin }`        |
| POST   | `/player/v1/rooms/:roomId/bookings/:id/end` | `{ pin }`. רק להזמנה שנעשתה במסך      |

התשובות לנגן כוללות רק את מה שמוצג: זמנים, "תפוס", וכותרת אם מותר. אין בהן מזהי משתמשים, שמות או אימיילים.

## 8. אבטחה (Threat Model מקוצר)

| איום                                     | בקרה                                                                                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| מסך מזמין חדר של ארגון אחר (IDOR / BOLA) | השרת בודק שהחדר שייך לארגון של המסך, ושה-manifest הנוכחי של המסך כולל Widget חדר עם `allowBooking` לאותו חדר. כל מקרה אחר מקבל 404.                                      |
| ניחוש PIN                                | הגבלת קצב לכל מסך ולכל ארגון: 5 ניסיונות כושלים ב-15 דקות, ואחר כך נעילה ל-15 דקות. ה-PIN נשמר כ-hash ‏(scrypt) ומושווה בזמן קבוע. ניסיונות כושלים נרשמים ביומן הפעולות. |
| הזמנה כפולה במקביל                       | אילוץ `EXCLUDE` במסד הנתונים. אם יש התנגשות, מחזירים 409 עם הודעה ידידותית.                                                                                              |
| "תפיסת" חדר מהמסך לאורך זמן              | הזמנה מהמסך: עד 60 דקות, רק מעכשיו, ועד 4 הזמנות בשעה לכל מסך.                                                                                                           |
| SSRF דרך קישור ICS                       | `safeFetch` הקיים: חסימת כתובות פרטיות, הגבלת הפניות, גודל עד 1MB ו-timeout.                                                                                             |
| ICS זדוני (קובץ ענק, הרבה חזרות)         | הגבלת גודל. הרחבת אירועים חוזרים רק לטווח של 60 יום, ועד 500 מופעים. הפענוח רץ ב-worker הקיים, לא בבקשת HTTP.                                                            |
| XSS מטקסט של יומן או מדריך               | הנגן מציג רק `textContent`, ואין HTML. ב-CMS ‏React מקודד ממילא.                                                                                                         |
| מפה של קומה                              | עולה דרך צינור המדיה הקיים, כולל סריקת ClamAV וזיהוי סוג הקובץ.                                                                                                          |

**הנחיות:**

- **כותרת פגישה:** לא לכתוב בה מידע רגיש (למשל "ראיון עבודה עם…"). זה יופיע כרמז בטופס, והכותרת מוסתרת במסך כברירת מחדל.
- **שמות אנשים במדריך הבניין:** בעלי תפקידים, למשל "ד"ר כהן, קומה 2", הם מידע אישי שמוצג בפומבי. נדרשת הסכמה של אותם אנשים, ומוצגת לכך אזהרה בעורך. **דורש בדיקה משפטית.**
- **מסמכים:** טיוטת מדיניות הפרטיות תעודכן בסעיף על הזמנות חדרים.

## 10. נגישות

- **ממשק הזמנה בלוח הניהול:** טופס מלא, בלי תלות בגרירה. לוח היום הוא טבלה עם כותרות שורה ועמודה, ואפשר לנווט בו במקלדת.
- **מסך החדר:** פנוי ותפוס מסומנים בטקסט ובאייקון, לא רק בצבע. ניגודיות AA. כפתורי מגע בגודל 56×56 לפחות.
- **מקלדת ה-PIN:** כל כפתור הוא `button` עם שם נגיש, ויש הודעת שגיאה מוקראת (`aria-live`).
- **מדריך בניין:** שימוש במנגנון המגע הקיים (Tab, ‏Enter וחזרה אוטומטית).
- **בדיקות axe** לכל עמוד חדש.

## 12. קבצים עיקריים
