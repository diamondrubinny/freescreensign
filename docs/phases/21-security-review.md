# שלב 21: סקירת אבטחה פנימית לקראת v1.0

**סטטוס:** אושר (29.10.2026): מסמך ממצאים מלא שמתפרסם במאגר אחרי התיקונים, וסריקת ZAP אקטיבית ידנית וגם שבועית ב-CI מול סביבת בדיקה מבודדת. גרסת ASVS: ‏5.0.0 (מאי 2025), שאומתה מול [אתר OWASP](https://owasp.org/www-project-application-security-verification-standard/).

## 1. מטרה

למצוא ולתקן חולשות לפני v1.0, ולהשאיר בדיקות שמונעות מהן לחזור.

**מה זה לא:** סקירה פנימית **אינה** בדיקת חדירות חיצונית. לפני v1.0 עדיין נדרש **בודק חדירות מקצועי**, כפי שכתוב ב-[PLAN.md](../PLAN.md). הסקירה הזאת מקטינה את מה שהוא ימצא, ומכינה לו חומר.

## 2. משטח התקיפה (מצב נוכחי)

| נקודת כניסה                       | אימות                     | היקף                                                         |
| --------------------------------- | ------------------------- | ------------------------------------------------------------ |
| `/api/v1/orgs/:orgId/...`         | Session (עוגייה) + תפקיד  | כ-95 נתיבים. צופה, עורך או מנהל                              |
| `/api/v1/auth`, ‏`/me`, ‏`/setup` | ציבורי או Session         | כ-27 נתיבים: התחברות, SSO, ‏MFA, איפוס סיסמה, הזמנות         |
| `/player/v1/...`                  | טוקן מכשיר (או קוד חיבור) | Manifest, מדיה, Widgets, ‏WebSocket, הזמנת חדר במסך מגע      |
| `/api/integrations/v1/...`        | מפתח API עם הרשאות        | מצב מסכים, התראות חירום, טקסט ב-Widgets                      |
| `/api/v1/operator`                | מפעיל השרת                | מצב השרת                                                     |
| **יוצא מהשרת**                    | `safe-fetch`              | Webhooks, יומן ICS, טבלת נתונים, מאגר התמונות, ספק ה-AI, SSO |
| **קבצים**                         | העלאה                     | הסגר, ClamAV, קידוד מחדש, הסרת מטא-דאטה                      |
| **עטיפות**                        | —                         | Electron, אנדרואיד, Raspberry Pi, ‏Tizen ו-webOS             |

**כבר קיים:** ‏RLS בבסיס הנתונים, בדיקות הפרדה בין ארגונים בחלק מהנתיבים, gitleaks, ‏Trivy, ‏CodeQL, ‏ZAP לא מאומת ו-SBOM.

2. **21.2 סקירה ידנית (S5):** לפי ASVS, תחום אחר תחום. כל ממצא מתוקן עם בדיקה.

   - עדכון [PRODUCTION-CHECKLIST.md](../PRODUCTION-CHECKLIST.md) ושחרור 0.11.0.

## 5. בדיקות

- **אוטומטי:** טבלת המדיניות, המטריצה, וכל ממצא עם בדיקה שנכשלת על הקוד הישן.
- **ZAP:** פסיבי בכל commit; אקטיבי ידני.
- **E2E ו-axe:** כמו היום, כדי לוודא שהתיקונים לא שוברים זרימות או נגישות.

## 6. סיכונים ומגבלות

- **כיסוי:** סקירה פנימית לא תמצא הכול, ובמיוחד לא בעיות לוגיקה שהכותב עצמו לא חשב עליהן. לכן נדרש בודק חיצוני.
- **סריקה אקטיבית:** עלולה למלא את בסיס הנתונים בזבל או להפעיל Webhooks. רצה רק מול סביבת בדיקה מבודדת.
- **שינויים שוברים:** תיקון הרשאה עלול לחסום שימוש קיים (למשל עורך שעשה פעולה שהייתה צריכה להיות של מנהל). כל שינוי כזה ייכתב ב-UPGRADING.
- **פרטיות:** הסקירה לא אוספת מידע אישי. נתוני הבדיקה מומצאים.
- **משפטי:** הסקירה אינה אישור תאימות לתקן או לחוק.

## 7. החלטות שהתקבלו

1. **מסמך הממצאים:** מלא, ומתפרסם במאגר אחרי התיקונים.
2. **סריקה אקטיבית:** ידנית, וגם ריצה שבועית אוטומטית ב-CI מול סביבת בדיקה שנבנית בתוך ה-CI.
